# 产品需求

本文只定义功能和用户可见行为；实现与数据格式见 [design.md](design.md)，用法见 [../README.md](../README.md)，未完成能力见 [tasks.md](tasks.md)。

## 范围与证据

帮助用户了解关注产品的新漏洞、影响版本、修复版本和后果，决定是否升级或查看详情。不预先采集本机版本，不判断本机可利用性；系统维护的依赖默认交给系统更新，自管或捆绑依赖须有明确产品归属。

支持 GHSA、项目安全公告、OSV、NVD、CVE、KEV。同一漏洞的不同编号和来源应合并，无 CVE 的有效公告仍保留。仅作为运行环境或明确不受影响的产品不得据此收录。撤回信息保留，但不参与有效评级和建议。影响范围、修复版本、后果缺少依据时明确未知，不推断“某版本修复全部漏洞”，保留原始出处。

## 更新

- `update` 可筛选产品、最低严重性、来源和回溯范围；默认最近三天、High + Critical。发现新漏洞及评级、范围、修复和撤回变化，不改变摘要展示历史，不影响未选产品。
- 重复更新应减少无变化内容的下载；改变展示等级或产品子集不应触发无关产品重采集。显示来源进度、请求与数据量、复用及内容变化统计。
- 来源失败不阻止其他来源完成；保留可用信息，指出失败和可能过期的范围。中断后可继续利用已完成工作。无法覆盖指定历史范围时明确报错，不能将缺失当作没有漏洞。
- NVD 每次目标更新选中产品的三分之一，向上取整；从未检查、相关配置变化或满72小时未成功检查的产品必须更新，允许超额。其余优先补选最久未更新的产品，按 UTC 日期分组、同日随机。每次运行独立计算配额，不扣除当天已更新数量；空结果也算成功检查。`--nvd-full` 或显式回补可强制检查全部选中产品。已知漏洞应定期复核，不因关键词变化或暂时查不到而误认撤回。
- KEV 检查最近两个自然月加入的条目，独立于通用回溯范围。按 Critical 优先级收录和筛选，同时保留原始严重性；新增 KEV 身份属于应再次展示的重要变化。

## 摘要

`summary` 只使用已收录信息，不联网补抓。默认最近三天、仅 Critical、仅未展示或有重要变化的内容；可筛产品、最低等级、时间和展示状态。空结果无输出。成功输出后记为已展示；筛掉或输出失败的内容不计入历史。忽略历史或仅看已展示内容时不改变历史。

默认输出无标题的产品表格：产品、KEV/Critical/High 个数、受影响版本、公告修复版本、证据标签。三类计数互斥，基于本次实际展示的活跃漏洞。版本只属于当前产品，保留组件、平台和分支差异；合并重复范围，不掩盖版本空隙或未知条件。Chrome 同组件稳定修复版本可汇总为最高升级目标，缺失修复信息仍须提示。缺陷类型与后果区分，不将任意代码执行自动称为远程执行。

`--list` 为窄屏格式：每软件五行，依次为名称、三类计数、受影响版本、公告修复版本、中文后果，随后空一行。名称前加 `## `，其余行前加 `- `；筛选和历史规则与表格相同。

可配置跨机器最低版本，仅影响摘要。只有证据足以确认所有受影响版本均低于门限时才隐藏；门限或更高版本可能受影响、无法比较或范围未知时保留。可临时忽略门限；被隐藏内容不记为已展示，门限不影响更新、详情或收录范围。

## 详情

`detail` 离线查看一个产品，默认最近三天、High + Critical（含 KEV），可指定确切等级、起始时间或取消时间限制。注明展示范围，不受展示历史和最低版本门限影响，也不修改历史。

先按漏洞编号展示原始描述，不自动翻译、拼接多源正文或推断，缺失时明确提示。末尾总表包含编号、原始威胁级别、公告时间、受影响版本、中文后果、原始链接；未知信息明确标注。版本应可读，不输出评分或原始证据数据转储。

## 运行与数据保护

结果与日志分离，支持输出到文件和接入其他工具。同一数据目录的命令互斥，冲突立即报错；不同目录可独立运行。慢来源不应阻塞其他来源；中断时停止后续请求并显示等待进度。

存储升级须支持离线迁移，保留原数据、采集进度和展示历史，拒绝覆盖已有目标；迁移不能改变报告。网络缓存损坏应能重建，不妨碍离线查看。空间维护失败须提示，不能使已保存结果失效。

展示历史不代表通知投递成功。当前不自动调用 AI，不自动通知或定时运行。
