# 产品需求

## 目标与范围

帮助用户了解关注产品的新漏洞和重要变化，并决定是否升级或进一步查看详情。关注范围包括 AI 工具、开发工具和浏览器。不预先采集本机版本，不把产品公告等同于本机可利用；系统维护的依赖默认交给系统更新，自管或捆绑依赖需有明确归属依据。

## 更新漏洞信息

通过 `update` 更新本地漏洞信息，可选择产品、最低严重性、数据源和回溯时间。默认收录 High + Critical，可选择仅 Critical。更新某些产品不影响其他产品的信息；更新不改变摘要的已展示状态。

应同时发现新漏洞和已有漏洞的重要变化，包括修复办法、影响范围、等级和撤回变化。支持 GHSA、项目安全公告、OSV、NVD、CVE、KEV；同一漏洞的多个编号和来源应合并，无 CVE 的有效公告仍保留。仅作为运行环境、被明确标为不受影响的产品不得据此收录。已撤回来源保留供查阅，但不参与有效评级、产品归属、版本建议和后果汇总。

本地缓存应避免重复存储配置等公共信息；存储优化应兼容已有缓存，不能丢失检查进度或改变报告。可重建的网络缓存损坏时应能重新获取，不阻止离线报告。

重复更新应尽量避免重新下载未变化的信息。在保持覆盖完整性的前提下减少调用次数和传输量。用户应能看到各来源的请求次数、响应数据量、缓存复用和新增/变化条数。改变展示等级或只更新部分产品，不应导致无关产品重复采集。

某个来源失败时，其他来源仍能完成；保留已有可用信息，明确提示失败和可能过期的范围。中断后再次运行应尽量复用已完成的工作。无法覆盖请求的历史范围时必须明确说明，不能把缺失当作没有漏洞。

## 产品摘要

`summary` 不联网，使用已收录的信息。可再次筛选产品、最低严重性、最近多少天发布或更新，以及是否已经展示。默认最近三天、High + Critical、仅未展示或内容有重要变化的条目；不需要展示的内容不输出。

产品可配置跨机器最低版本门限，仅 summary 使用。只有证据足以确认所有受影响版本均低于门限时才隐藏；门限本身或更高版本仍可能受影响、范围未知或无法比较时保留。未配置时行为不变。门限不影响 update、detail 和收录范围，被隐藏条目不记为已展示。summary 可临时跳过最低版本门限，不修改产品配置；其他过滤和展示历史规则保持不变。

摘要仅输出产品表格，不附加标题或解释段落，方便其他工具读取。摘要回答以下问题，而非堆叠漏洞编号和评分：

1. 每个产品有几个 Critical、几个 High？计数是本次过滤后实际展示的活跃漏洞数。
2. 哪些版本受影响？只展示当前产品的范围和修复版本，不能混入同一公告中的其他独立产品；保留当前产品的平台、组件和版本分支差异。
3. 升级到什么版本可以修复？部分信息缺失时明确说明，不能误称某个版本消除全部漏洞。
4. 最严重的后果是什么？用 RCE、Crash、Sandbox Escape 等标签表达；UAF 等缺陷类型与后果区分，不把任意代码执行自动称为远程执行。

摘要默认记住已成功展示的内容。第二次运行且没有重要变化时无输出；被筛选掉或输出失败的内容不得标记为已展示。允许忽略展示历史，或仅查看已展示条目，这两种查看均不改变历史。

没有充分证据的影响范围、修复版本和后果显示“未知/待核实”，保留原始出处。自动分析必须说明依据与局限，不编造攻击链或本机可利用结论。

## 漏洞详情

`detail` 不联网，选择一个产品和一个确切级别，以 Markdown 逐条展示该产品该级别的缓存漏洞。默认仅展示近3天发布或更新的条目；可指定回溯天数、起始时间，或取消时间限制。输出注明时间范围，不受已展示状态限制，不改变展示历史。

每条包含编号/别名、标题、级别、后果或缺陷标签、受影响范围、修复版本、公告正文、来源评分、发布时间、更新时间及原始链接。来源评级分歧应可见，厂商评级与 CVSS 不得混淆；已撤回公告默认不计入活跃漏洞。

## 使用边界

显示操作只能使用已收录范围，不能默认为它补抓了较低级别或未关注产品的信息。展示历史不代表通知投递成功。完整报告可临时生成，不要求长期保存。

AI 深度解读、自动通知及投递确认、每日调度属于后续能力；当前不自动调用 AI。

## 输出与版本表达

命令结果应能接入其他工具，日志和诊断默认写 stderr，不混入 stdout。摘要的受影响版本和公告修复版本按同一产品、同一组件/平台分别合并，吸收冗余条件；保留不同组件、版本空隙及无法可靠解释的表达式。

Chrome 摘要应合并仅大小写不同的组件名，并将同一组件的稳定修复版本汇总为覆盖本次漏洞的最高升级目标；不同平台或明确分支保持独立，修复信息缺失仍须提示。

## 命令互斥

同一数据目录内的 update、summary、detail 全部互斥。已有命令运行时，新命令明确报错退出，不等待；update 内部的数据源仍可并发。不同数据目录可独立运行，但不得交叉共享状态或展示历史。

## 抓取效率与独立运行

各数据服务应独立推进，慢服务或限流等待不阻塞其他服务；同一服务避免突发并发。CVE 优先启动，并保留受控的详情下载并发。优化必须保持覆盖与失败恢复能力；条件请求、批量下载和分页早停不得把缺失或失败误判为没有漏洞。用户可关闭 CVE 压缩包加速作对照。

已收录的 NVD 漏洞应定期复核，不因产品关键词被删除而漏掉评级、影响范围或撤回变化。复核失败或暂时查不到时保留旧信息并提示可能过期，不能当作漏洞已撤回。

KEV 每次检查最近两个自然月加入目录的条目，以收录日期为准，独立于通用回溯参数。已被利用不等同于严重性评分，KEV 按 Critical 优先级收录和筛选，保留原始严重性。摘要单列 KEV 数量，Critical/High 仅统计非 KEV，不重复计数。KEV 仍受产品、时间、最低版本和展示历史过滤；新增 KEV 身份是重要变化，应再次展示。详情在 Critical 分类中显示 KEV，并说明其优先级与原始评分的区别。

更新中断时应停止后续请求，保存已完成来源，未完成任务不推进检查点；等待期间定期显示正在运行的来源。
