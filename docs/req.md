# 产品需求

## 目标与范围

帮助用户了解关注产品的新漏洞和重要变化，并决定是否升级或进一步查看详情。关注范围包括 AI 工具、开发工具和浏览器。不预先采集本机版本，不把产品公告等同于本机可利用；系统维护的依赖默认交给系统更新，自管或捆绑依赖需有明确归属依据。

## 更新漏洞信息

通过 `update` 更新本地漏洞信息，可选择产品、最低严重性、数据源和回溯时间。默认收录 Critical，可选择 High + Critical。更新某些产品不影响其他产品的信息；更新不改变摘要的已展示状态。

应同时发现新漏洞和已有漏洞的重要变化，包括修复办法、影响范围、等级和撤回变化。支持 GHSA、项目安全公告、OSV、NVD、CVE；同一漏洞的多个编号和来源应合并，无 CVE 的有效公告仍保留。

重复更新应尽量避免重新下载未变化的信息。在保持覆盖完整性的前提下减少调用次数和传输量。用户应能看到各来源的请求次数、响应数据量、缓存复用和新增/变化条数。改变展示等级或只更新部分产品，不应导致无关产品重复采集。

某个来源失败时，其他来源仍能完成；保留已有可用信息，明确提示失败和可能过期的范围。中断后再次运行应尽量复用已完成的工作。无法覆盖请求的历史范围时必须明确说明，不能把缺失当作没有漏洞。

## 产品摘要

`summary` 不联网，使用已收录的信息。可再次筛选产品、最低严重性、最近多少天发布或更新，以及是否已经展示。默认最近三天、High + Critical、仅未展示或内容有重要变化的条目；不需要展示的内容不输出。

摘要回答以下问题，而非堆叠漏洞编号和评分：

1. 每个产品有几个 Critical、几个 High？计数是本次过滤后实际展示的活跃漏洞数。
2. 哪些版本受影响？保留必要的平台、组件和版本分支差异。
3. 升级到什么版本可以修复？部分信息缺失时明确说明，不能误称某个版本消除全部漏洞。
4. 最严重的后果是什么？用 RCE、Crash、Sandbox Escape 等标签表达；UAF 等缺陷类型与后果区分，不把任意代码执行自动称为远程执行。

摘要默认记住已成功展示的内容。第二次运行且没有重要变化时无输出；被筛选掉或输出失败的内容不得标记为已展示。允许忽略展示历史，或仅查看已展示条目，这两种查看均不改变历史。

没有充分证据的影响范围、修复版本和后果显示“未知/待核实”，保留原始出处。自动分析必须说明依据与局限，不编造攻击链或本机可利用结论。

## 漏洞详情

`detail` 不联网，选择一个产品和一个确切级别，以 Markdown 逐条展示该产品该级别的全部缓存漏洞。默认不受摘要时间范围和已展示状态限制，不改变展示历史。

每条包含编号/别名、标题、级别、后果或缺陷标签、受影响范围、修复版本、公告正文、来源评分、发布时间、更新时间及原始链接。来源评级分歧应可见，厂商评级与 CVSS 不得混淆；已撤回公告默认不计入活跃漏洞。

## 使用边界

显示操作只能使用已收录范围，不能默认为它补抓了较低级别或未关注产品的信息。展示历史不代表通知投递成功。完整报告可临时生成，不要求长期保存。

AI 深度解读、自动通知及投递确认、每日调度属于后续能力；当前不自动调用 AI。
